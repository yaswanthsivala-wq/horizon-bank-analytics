## Temporal contract

Analytical range is 2024-09-01 through 2026-08-31 inclusive, exactly 24 calendar months; half-open Chicago interval [2024-09-01 00:00, 2026-09-01 00:00). No extra RC-01 warm-up events. Opening state effective before the window may be represented only where needed for retained state/dependencies, not additional analytical events. All 730 business dates have expected manifests and applicable snapshots.

Source business date D covers Chicago [D 00:00, D+1 00:00). Snapshot as_of_cutoff_at is D+1 midnight; selected state is immediately before that exclusive boundary, represented for point matching at cutoff minus one microsecond. The initial delivery is due 04:30 Chicago on D+1; approved synthetic late allowance ends 05:30; 06:00 publication gate remains unchanged. Source events before cutoff are eligible; later corrections use revision lineage and a later candidate. These are synthetic scheduling conventions, not observed SLAs.

Contractual due_date remains a date. Obligation branch matching uses due_date at 00:00 America/Chicago converted to UTC, inclusive start. Branch changes exactly at midnight apply to that due date. Snapshot/K07 date-based end-of-day state uses the snapshot convention above. Other attribution instants remain exactly DD-12's event/effective instants, including final_closed_at for K08 and closed K10.

Every supplied event instant carries an explicit UTC offset and is normalized to UTC(6). America/Chicago uses IANA tzdb 2026a as the specification version; later implementation must record/verify the library's version. Ambiguous fall-back local times without an offset/fold are invalid; nonexistent spring-forward times are invalid, never shifted. Supplied offsets must match the zone at that instant. Local day lengths can be 23/25 hours; no fixed 24-hour addition for local calendar boundaries. Midnight dates are converted through the zone, never by a constant offset. Examples: 2025-03-09 00:00 Chicago = 06:00Z; 2025-03-10 00:00 = 05:00Z; 2025-11-02 00:00 = 05:00Z; 2025-11-03 00:00 = 06:00Z. SLA elapsed hours use UTC elapsed time, not wall-clock subtraction.

SRC-02 proposed posted_at is required exactly for POSTED versions and null for PENDING/FAILED/CANCELLED. It is the offset-qualified source posting instant, >= paid_at (payment-event time). Status evolution preserves immutable versions and source event identity; POSTED attribution uses posted_at, nonposted attribution uses paid_at. No missing posting instant is replaced with paid_at. Original POSTED events remain when separate REVERSAL/REFUND events arrive. An illegal nonposted version carrying posted_at or POSTED missing it is an invalid-contract scenario.

## History transitions and correction semantics

Branch/region identities never reuse IDs. Effective versions and account/loan SERVICING/ORIGINATION, customer-home and complaint RESPONSIBLE assignments use half-open intervals. Same-instant transfer ends old and begins new. Ordinary changes take effect at their stated instant; backdated corrections name the affected interval, predecessor, source version and simulated review references. Region changes split branch versions and dependent assignment references where necessary, without relabeling older facts. Closure ends the branch interval; affected active servicing/responsibility must move through explicit source assignments. Merger successors are explicit and never grant access. Customer home is independent of account/loan assignments. Complaint transfer does not reset creation, SLA clock or creation priority. No history gap is filled by inference.

## Proposed synthetic domains and amounts

Canonical codes are delivered identically to their mapping targets with a versioned IDENTITY_SYN_V1 mapping. Unknown raw code X_UNMAPPED is reserved for negative fixtures, never silently mapped. Transactions: SUCCESSFUL, POSTED, FAILED, DECLINED, CANCELLED, VOIDED, REVERSED, PENDING. Synthetic RC-01 finalized eligibility is SUCCESSFUL/POSTED only; all other statuses excluded. Loans: ACTIVE, DELINQUENT_ACTIVE, FORBEARANCE_ACTIVE, PAID_OFF, CLOSED, CHARGED_OFF; UNKNOWN only explicit coverage scenarios. Payments: PENDING/POSTED/FAILED/CANCELLED. Complaint: OPEN, IN_PROGRESS, REOPENED, CLOSED; priorities Critical/High/Medium/Low. Fraud case: OPEN/CLOSED; severity LOW/MEDIUM/HIGH/CRITICAL. Restriction states: NONE/RESTRICTED/FROZEN/BLOCKED. Ownership roles PRIMARY/JOINT; borrower roles PRIMARY/CO_BORROWER. Business classification domains: segment RETAIL/SMALL_BUSINESS; account_type CHECKING/SAVINGS; loan_type PERSONAL/AUTO/MORTGAGE; transaction_type TRANSFER/PAYMENT/WITHDRAWAL/DEPOSIT; complaint channel PHONE/WEB/BRANCH; alert reason VELOCITY/AMOUNT/RESTRICTION. These are invented fixture domains, not claims about a bank.

USD and EUR are separate currencies, both two minor units, represented at inventory decimal scale 4 with trailing zeros. No FX or cross-currency netting. Loans and all contractual monetary children share currency; account currency is not invented as a new field. Obligations/allocations are positive in baseline fixtures; unapplied is >=0. Optional zero obligation scenario is not used to infer a business rule. Transactions use signed debit/credit values; finalized RC-01 compares absolute nonzero values per approved rules.

Payment contract uses gross original-payment allocation evidence: posted amount = original active contractual allocations + unapplied. Adjustment references identify affected components/unapplied portions separately through application_reference/source_reference evidence; component effects sum exactly to adjustment magnitude and cannot exceed available original component/unapplied amounts. No automatic reallocation/waterfall. Adjustments do not reduce original gross allocation evidence; net cash is displayed separately as POSTED minus adjustments, never mislabeled as the gross equation. Correcting a source allocation selects a reviewed replacement version; it is not a business reversal. This synthetic representation preserves both approved payment equations.

All other constrained fields use exactly inventory/policy enums. Opaque reference/identifier fields use deterministic prefix plus source-qualified ordinal; free reason text is sanitized scenario code only. Optional fields are null unless their documented applicability condition holds. Conditional fields are populated if and only if the condition applies; negative scenarios explicitly violate it. Numeric threshold values remain those already approved, not invented replacements.
