# Security, RLS and masking enforcement

DD-08/DD-12 policy is unchanged. The foundation establishes only NOLOGIN role groups/owners, schema boundaries and restrictive defaults. It creates no RLS policies, protected business tables, views or implemented masking. All enforcement below is deferred and requires tests before claims.

Trusted connection handling binds principal and exactly one selected active role. Never accept a freely user-set GUC as authentication. Avoid roles with inherited access unions. Separate application connections from object owners, superusers and BYPASSRLS. Future policies enable and where appropriate FORCE RLS; even FORCE does not confine superusers/BYPASSRLS, so owner/bootstrap credentials are outside the application persona boundary. Guarded SECURITY DEFINER functions require fixed qualified search_path, minimal owner rights, revoked PUBLIC EXECUTE, validated inputs and no dynamic identifier injection.

Current approved effective unrevoked entitlement is re-evaluated for every new query and export execution. Restrict stale long-lived snapshots/caches; transaction isolation and authorization evaluation must not make revoked grants remain effective. Explicit deny precedence and dimension intersection are encoded once and tested across all surfaces. Current region scope expands to current stable branch members while historical labels remain as published. Predecessor scope requires explicit approved mapping/current grant; merger alone grants nothing. Analysts remain case-scoped; Executive/Operations aggregate ceilings remain. No automatic source-owner or Administrator business access.

Reporting views/functions expose fixed mask+final four, required deidentified projections and authorized aggregates; users have no raw/base-column privileges. Table-level RLS is not column masking. Distinguish SQL owner privilege from the simulated Administrator. Audit payloads carry sanitized codes/counts, never names, full account numbers, aliases or narrative/filter secrets. Source raw/quarantine privileges are scoped; exceptions use required approval and recheck.

Export preparation uses isolated restricted temporary output; authorization is checked again before release, and expiry/revocation suppresses and disposes preparation output without returning sensitive rows. Error messages, FK/unique failures, logs, result caches and test assertions must not leak Restricted values. Negative fixtures use sentinel synthetic secrets; assert absence without dumping those strings to evidence. Connection cleanup clears persona/context before reuse.

Deferred tests: all approved persona allow/deny cases, unselected second role, expired/revoked grants mid-export, field/tooltips/API/export parity, orphan scope, current-region/historical-label behavior, owner bypass demonstration in isolated admin setup, inference through errors and masking failures. No RLS/security runtime testing occurred.
