# Temporal versions and atomic publication

Immutable accepted events, snapshots, schedules, obligations and history corrections retain original records and full predecessors. Changes in operational current pointers or candidate workflow state do not rewrite released facts/approvals. Ordinary effective end is represented by a new selected interval version where necessary; prior published interpretation survives. No cascade update reassigns historical FKs.

Approved synthetic temporal rules are inherited unchanged: America/Chicago local dates, UTC(6) instants, due_date retained as date with local-midnight lookup, snapshot cutoff exclusive and matching at cutoff minus one microsecond, offset-qualified event timestamps, rejected ambiguous/nonexistent local times, POSTED at posted_at and nonposted at paid_at. Endpoints are half-open. Original effective/event retention anchors never reset.

Overlaps are rejected within selected candidate/publication histories, not across all preserved revisions. A physical selected-interval projection contains candidate/publication identity, full subject identity, role, interval and immutable-version FK. It requires exactly-one coverage at required attribution instants; GiST exclusion alone cannot prove gap-free coverage. Corrections and concurrency lock the affected stable subject or use serializable transactions with retry; checks and insert must not race. Type/purpose/date/currency consistency and predecessor acyclicity are independently enforced.

Publication sequence (design, not executable processing): freeze candidate manifest/configuration/source/membership inputs; validate controls and current authorization/required approval evidence; serialize release for the business date; record release decision and publish all five source memberships in one transaction; atomically select new successful version. Rollback leaves prior success visible. Audit failed attempts separately after rollback without sensitive payload. Failure before any success returns Data unavailable. No partial successful daily publication or mixed-version report. Revocation/expiry is rechecked independently of the historical publication.

Immutable membership binds exact event/snapshot/organization and assignment versions. Historical labels use fact attribution time; current region grants expand using current approved hierarchy, never the report's old region membership. Corrections only restate retained affected intervals, recalculate approved impacts and use a new publication. Old membership remains unless expired under DD-10. An index, cache or current pointer is never authoritative history.

Deferred verification: concurrency/race, stale candidate, correction replay, crash before/after release, orphan membership, version mismatch, duplicate selected natural key and failed first publication. No such tests were run.
